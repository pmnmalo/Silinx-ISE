In short:
- Silinx HLS: Vitis HLS's mixed control and data driven example now builds. The number of channels of an `hls::split` / `hls::merge`, the size of an array of streams or of tasks, may be any integer constant C++ allows there (a `const` / `constexpr`, an enum, a class's `static const` member, `sizeof`, a template's parameter), and an array of tasks (`hls::task t[NP];`) may be started in an unrolled loop.

In detail:
- **Silinx HLS: `hls::split::round_robin<int, NP>` with NP a named constant, and arrays of `hls::task` (#1898):** the number of channels of a split or a merge, and the size and the indexes of an array of streams, are constant expressions whose names are the integer constants declared before them, as C++ and Vitis HLS take them: `const` / `constexpr` integers (lists of them too), enum constants (`E::A` of an enum class), a class's `static const` members (`C::N`), `sizeof` of a type of C, a block's gone at its end (`core/cpp-consts.js`); where they had to be literals. A template's parameter too: those passes run again once the templates are made. `hls::task t[N];` is an array of tasks, each started as `t[k](f, a…);` or in a loop of constant bounds (any start, `<`, `<=`, `>`, `>=`, `!=`, a step of `++`, `--`, `+=`, `-=`, `i = i + c`; its body unrolled), each element a task of its own in the C simulation and in hardware; another use, an element outside the array or started twice is said, once. The C simulation tells two tasks started at the same place apart by their names. A `const` integer declared in a DATAFLOW region is folded where it is used (a call's argument too) instead of making the region sequential. The example passes the C simulation, the synthesis and the co-simulation (the corpus's `expected.json`).
