# Differential tests against Yosys

Silinx's Verilog / VHDL front end, its simulator and its open synthesis (`core/synth-verilog.js`
+ Yosys in WebAssembly, YoWASP) are checked by comparing simulations: a design is simulated as RTL
by Silinx and as a Yosys netlist, with the same seeded random stimulus, cycle by cycle
(`test/diff-synth.js`). The netlist is simulated cell by cell (`test/fpga-sim.js` netlistSim, or
Silinx's primitive models for block RAMs, DCMs, tri-state buffers).

Two netlists are possible for a design:

- **Silinx's synthesis path**: Silinx elaborates the design, writes it as one flat module, Yosys maps
  it (`synth_xilinx -family xc3se -ise`). This checks `core/synth-verilog.js` and the simulator.
- **Yosys's own front end** (Verilog only): Yosys reads the original text. Silinx's parser and
  elaborator are then checked against an independent reading of the language (in the first path
  a front-end mistake would be on both sides).

## Comparison rules

- Clocks: the inputs that reach a clock pin in the netlist, and the ports named `clk*` / `clock*`.
  Inputs change a quarter period after the rising edge; outputs are sampled before the next one.
- Resets (`rst`, `reset`, `clr`… active low when named `…n`, `…_n`, `…_b`, `n…`) are asserted in
  the first two cycles, then with a probability of 2 %. Other inputs are random (with all-zero,
  all-one and one-hot values mixed in).
- Power-up: the netlist's flip-flops start at their INIT values; the RTL's signals at their
  declared initial values, 0 when there is none (as the FPGA). If that differs, the RTL is run
  again with the X's kept (the language's power-up): Yosys may give anything to a register or a
  memory word that is never set.
- An output bit the RTL has at X or Z is not compared (don't care); every known bit must be equal.
- A difference is reported with the design, the cycle, the inputs and both outputs.

## Yosys's test designs: `npm run test:corpus`

`scripts/fetch-yosys-tests.mjs` (`npm run fetch:yosys-tests`) downloads YosysHQ/yosys at a pinned
commit (v0.68, the Yosys of YoWASP; ISC licence) into `.cache/yosys-tests/` (git-ignored; the
files are never committed) and keeps `tests/simple`, `tests/asicworld`, `tests/hana`,
`tests/various`. (`tests/vloghtb` has no designs in the repository: its script downloads them,
generated by VlogHammer, which `npm run test:vloghammer` covers.)

`test/corpus/run-corpus.mjs` runs every file in worker threads: Silinx parses and elaborates it,
and each top module is compared with both netlists. `test/corpus/expected.json` holds the expected
result of each `file:top` (Yosys's front end) and `file:top (synth)` (Silinx's synthesis):
`pass`, `unsupported: <stage>: <reason>`, `mismatch: <reason>` or `error: <stage>: <reason>`.
The run fails on a regression (a key expected to pass that does not); newly passing keys are
listed, and `--update` records the results. Options: `--filter text`, `--jobs n`, `--cycles n`,
`--shard k/n` (every n-th file from the k-th) and `--timeout s` (900 s): a file that takes longer fails
the run, unless `expected.json` has the file itself failing as a whole (`hana/hana_vlib.v`, out of memory or
out of time); the run prints its ten slowest files.

The nightly (`.github/workflows/nightly.yml`) runs it in two jobs at once, `--shard 1/2` and `2/2`, 4 jobs
each (#343): Silinx's synthesis of a module is up to 7 Yosys runs (its mappings onto LUT4s alone, with the
wider functions, for depth, balanced again with and without the LUT delays, and the carry chains of logic
written as gates: Optimization Effort High, the default of `synthesizeOpen`), and the whole corpus in one
job grew from 46 minutes (12 October) to 52 (14 October) and past the job's 60 (15 and 16 October); in two,
36 and 22 minutes (17 October).

`test/corpus/warnings.json` holds the warnings (and notes) Silinx gives: for each file those of the
parser, for each `file:top` those of the elaboration (`"line: message"`). A new warning fails the
run too (a construct now read must not bring a spurious warning; a new check is reviewed before
`--update` records it); a warning no longer given is listed.

## VlogHammer-style random modules: `npm run test:vloghammer`

`test/corpus/vloghammer-gen.mjs` ports the random module generator of VlogHammer
(https://github.com/YosysHQ/VlogHammer, `scripts/generate.cc`, by Claire Xenia Wolf, ISC licence):
the same families (expression, wideexpr, partsel, and the single-operator families), the same
xorshift32 sequence and seeds. `test/corpus/vloghammer.mjs` compares Silinx's simulation with
Yosys's netlist of the same text (`synth` to gates by default; `--flow xilinx` for synth_xilinx;
`--synth` also checks Silinx's synthesis path) on random input vectors, and reduces a failing
module (one output kept, expression nodes replaced by an operand or a constant) to a small text.

    npm run test:vloghammer -- --seed 0 --count 1000 [--families expression,partsel] [--synth] [--out dir]

Results, Yosys's front end: `--seed 0 --count 400` and `--seed 50 --count 2000` (module indices
0–299 of each family): 2399 of 2400 agree; the one left (`wideexpr_00262`) is a Yosys difference
(below). Through Silinx's synthesis path (`--synth`): `--seed 100 --count 64` all agree,
`--seed 200 --count 400` 399 of 400 (`partsel_00217`, open, below).

## Found and fixed

Simulator / elaborator (Verilog, IEEE 1364-2005 5.5 and others):
- a signed operand of an unsigned comparison, shift or `?:` was sign-extended (VlogHammer);
- the operands of nested context-determined operators did not take the sign of the whole
  expression: `u + (s1 + s2)` extended s1 and s2 by their sign (VlogHammer);
- `?:` of a signed and an unsigned operand of the same width was signed (VlogHammer);
- `case` expression and items: extended together, as signed only when all are;
- `?:` with a real operand was not real (simple/realexpr.v);
- a port connected straight to its actual read with the actual's signedness (simple/hierarchy.v);
- defparam through generate blocks was not applied (simple/hierdefparam.v);
- declarations in functions, tasks and named blocks with the name of a module port refined the
  port instead of declaring a local (simple/scopes.v, const_func_shadow.v);
- `not` / `buf` with several outputs (simple/verilog_primitives.v);
- an output variable's initializer and an unconnected input's default value (simple/defvalue.sv);
- an undeclared input of a gate primitive is an implicit net (asicworld full_subtracter_gates);
- a port declared twice is an error (various/pmux2shiftx.v).

Synthesis front end (`core/synth-verilog.js`):
- `>>>` of an unsigned value was an arithmetic shift (hana test_intermout.v f22_test);
- operands of unsigned expressions, `{s}` and selects of signed vectors kept their sign;
- a part-select starting below bit 0 lost its bits in range (simple/partsel.v);
- a `case` item wider than the expression was truncated;
- an unconnected input with a default value was left undriven;
- a workaround for Yosys sizing an xor of size casts inside a concatenation at the casts'
  operand width (asicworld gray_counter).

## Differences where Yosys appears wrong (not "fixed" in Silinx)

- `assign y = u >> (1'sb1 + (s & 6'sb001110));` (u unsigned [1:0], s signed [3:0], y [15:0]):
  for u = 3, s = 1 the shift amount is -1 as a 6-bit value, 63 unsigned (the right operand of a
  shift is unsigned), so y = 0; Yosys 0.68 shifts left by one (y = 6).
- `assign y3 = 1 ? -1 : 'd0;` with a 64-bit y3: the `?:` is unsigned ('d0 is unsigned), so -1 is
  extended from 32 bits with zeros (0x00000000ffffffff); Yosys gives all ones.
- `{a[7], (1'(a >> 1) ^ 1'(a >> 0))}`: the xor of two 1-bit size casts is 1 bit wide; Yosys 0.68
  makes it 8 bits wide inside the concatenation (and drops a[7]).

## Open

- `partsel_00217` through the synthesis path: Silinx's generated text and Yosys disagree on an OR of
  two size-cast bit selects (`32'(1'(x7 >> (29 - 32'(32'h4 + 32'(s3))))) | 32'($unsigned(1'(x6 >>
  32'(32'h7 + 32'(s1)))))` with `x6 = 29'(4'(x4 >> 10))`, `x4 = 26'(7'(x1 >> 21))`); Silinx's
  simulation of that text agrees with its simulation of the original, so it looks like another case
  of Yosys sizing the operand of a size cast by its context; not worked around yet.
